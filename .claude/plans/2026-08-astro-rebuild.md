# Rebuild nottingham.digital on Astro

## Context

`nottingham.digital` is a community-maintained directory of 19 tech meetups in
Nottingham. The repo *is* the site: GitHub Pages serves the branch root directly,
so `index.html` at the root is what visitors get.

Three problems motivate the rebuild:

1. **The content is trapped in markup.** All 19 meetups are hand-written `<li>`
   blocks inside a 170-line `index.html`. The repo's whole purpose is community
   contribution (see `contributor-guide.md`), but adding a meetup means editing a
   shared HTML file — the highest-friction, highest-conflict way to accept a PR.
2. **The payload is absurd for what it does.** `js/libs.min.js` (133KB, jQuery +
   moment.js) plus `js/event.min.js` exist to render four filter buttons, fetch
   next-event dates from `notts-digital.phpminds.uk`, and re-sort the list. The
   build tooling is Gulp 4, and `package.json` carries junk runtime deps
   (`npm`, `tar`, `fstream`, `hoek`, `sshpk`) left behind by Dependabot PRs.
3. **A rebrand is coming.** A new logo and colour scheme are planned, and today
   every colour is a hex literal scattered across `css/core.css`.

**Outcome:** the same site, statically generated by Astro, with each meetup as
its own data file, zero framework JavaScript, and every visual decision behind a
design token so the rebrand is a one-file change.

### Decisions taken

| Decision | Choice |
|---|---|
| Generator | **Astro** — Vite-based, but a real SSG (plain Vite would need a templating plugin bolted on) |
| Design | Keep the current identity, **rebuild it token-driven** so a new theme drops in cleanly |
| Deploy | **GitHub Actions** → `actions/deploy-pages` |
| Carry over | Category filters, PWA manifest + icons, print stylesheet |
| Drop | Live "next event" API fetch, Google Analytics, jQuery, moment.js, Gulp |

Work happens on the existing branch `claude/nottingham-digital-vite-pjypun`.

Deleted: `index.html`, `css/`, `js/`, `gulpfile.js`, `yarn.lock`,
`package-lock.json`, `manifest.json`, and the old `package.json` contents.

## Implementation

### 1. Scaffold

`npm create astro@latest` with the empty/minimal template, TypeScript strict, no
integrations. **Read the generated files before writing any config** — pin to
whatever API version the installed Astro actually uses (v5 puts the collection
schema in `src/content.config.ts` with a `glob()` loader; do not assume).

Rewrite `package.json` from scratch: `astro` as the only real dependency, scripts
`dev` / `build` / `preview`. Delete `yarn.lock` and the 206KB
`package-lock.json`; regenerate `package-lock.json` via `npm install`.
Add `dist/` and `.astro/` to `.gitignore`.

### 2. Content collection — the core change

`src/content.config.ts` defines a `meetups` collection loaded from
`src/content/meetups/*.yml`, schema:

```ts
name: z.string()
url: z.string().url()
summary: z.string()
cadence: z.string()              // "Second Thursday" | "No regular date"
category: z.enum(['tech', 'design', 'ops'])
links: z.array(z.object({ label: z.string(), url: z.string().url() })).default([])
```

Port all **19** meetups from `index.html` (lines 28–147), copy preserved
verbatim — do not rewrite anyone's blurb. Category split is
**13 tech / 4 ops / 2 design**; verify that total after porting.

Note `links` generalises the hard-coded `twitter` anchor. Twitter links port
across as `{ label: 'Twitter', url: ... }`, but the array shape means a group can
add Bluesky, Mastodon or LinkedIn later without a schema change.

`index.astro` sorts by `name` — matching the existing "Events ordered
alphabetically" note, which stays accurate now that the date-sort is gone.

### 3. Theming — built for the rebrand

`tokens.css` holds **every** colour, font, space and radius as custom properties
on `:root`; no other stylesheet may contain a hex literal. Categories get their
own tokens so a new palette is a three-line edit:

```css
--color-category-tech:   #F44E36;
--color-category-design: #3EC4AC;
--color-category-ops:    #F4BA4F;
```

Cards read theirs indirectly — `background: var(--color-category-{id})` resolved
from `data-category`, so adding a fourth category means one token plus one entry
in `categories.ts`, touching no component.

Dark mode: redefine the same token names inside a single
`@media (prefers-color-scheme: dark)` block in `tokens.css`. One block to
re-tune at rebrand time.

`Logo.astro` renders the "Nottingham Digital" wordmark today and is the single
file to replace when the logo lands — nothing else references the site name.

Carry over from `core.css`: 600px centred column, white cards on grey, Fira Sans
+ Fira Mono, the left category stripe with its icon at ≥600px. Modernise the
execution — fluid type, CSS grid, focus-visible rings.

### 4. Filters, without jQuery

`CategoryFilters.astro` renders real `<button>` elements with `aria-pressed`
(the current markup uses unfocusable `<li>` elements — keyboard users cannot
operate it at all). ~25 lines of vanilla JS set `data-active-category` on the
list container; CSS hides non-matching cards. A visually-hidden `aria-live`
region announces the resulting count.

No-JS safety: the filter bar is `display: none` by default, revealed by a
`.js` class that an inline script sets on `<html>`. Without JS, all 19 meetups
show and no dead controls appear.

### 5. PWA manifest

Rebuild rather than copy — the current `manifest.json` is broken
(`display: fullscreen` for a text directory, no `start_url`, no `theme_color`,
one icon missing its `type`). New `public/manifest.webmanifest`:
`display: browser` (or `minimal-ui`), `start_url: "/"`, `theme_color` and
`background_color` from tokens, all existing icons declared with correct sizes
and types. Move `img/*.png` to `public/img/`.

### 6. Deploy workflow

`.github/workflows/deploy.yml` — trigger on push to `main` plus
`workflow_dispatch`; permissions `contents: read`, `pages: write`,
`id-token: write`; concurrency group `pages`. Build job: `actions/checkout@v4` →
`actions/setup-node@v4` (Node 22, npm cache) → `npm ci` → `npm run build` →
`actions/upload-pages-artifact@v3` with `path: ./dist`. Deploy job:
`actions/deploy-pages@v4` in the `github-pages` environment.

### 7. Housekeeping

- Update `README.md` (dev commands, how to add a meetup) and
  `contributor-guide.md` — "edit index.html" becomes "add one YAML file". This
  is the contributor-facing payoff and should not be skipped.
- Move the stray `docs/.github/issue_template.md` to `.github/issue_template.md`,
  where GitHub actually looks for it. Small, adjacent, currently non-functional.

## Risks

**Nothing goes live until a repo admin flips Settings → Pages → Source to
"GitHub Actions".** Merging to `main` without that flip is not an outage — Pages
keeps serving the old branch-root files — but the new site will not appear, and
the workflow will fail at the deploy step. Flag this on handoff.

**The custom domain.** `public/CNAME` must ship in the build artifact or the
apex domain can drop after the source flip. Keep the root `CNAME` in place as
well until the flip is confirmed, then remove it as a follow-up. Verify
`dist/CNAME` exists and reads `nottingham.digital` on every build.

**Content is years stale.** The last content commit predates 2023; several
Meetup groups and most Twitter links are probably dead, and outbound network is
blocked in this session so none of it can be checked here. Content ports
verbatim — a link audit is a separate follow-up, not part of this rebuild.

## Verification

1. `npm install && npm run dev` — page renders at `localhost:4321`.
2. `npm run build` — clean build, no warnings.
3. **Static output is real HTML:** all 19 meetup names appear in `dist/index.html`
   (`grep -c 'meetup-card' dist/index.html` → 19). This is the central claim of
   the rebuild — the list must be in the HTML, not injected by script.
4. **Payload:** no jQuery or moment in `dist/` (`grep -ri 'jquery\|moment' dist/`
   → empty). Total JS should be well under 2KB.
5. `dist/CNAME` present and correct; `dist/manifest.webmanifest` valid JSON.
6. **Browser (Chromium + Playwright are preinstalled):** `npm run preview`, then
   drive it — screenshot at 1280px and 375px, click each of the four filters and
   assert the visible card count (all 19 / 13 / 2 / 4), tab through the filter bar
   to confirm keyboard operation, and load once with JavaScript disabled to
   confirm all 19 cards render and no dead filter bar appears.
7. Diff old vs new rendered text to confirm no meetup was dropped or reworded.
8. Commit and push to `claude/nottingham-digital-vite-pjypun`, then **open a PR
   against `main`**. The body should call out, up front, that a repo admin must
   set Settings → Pages → Source to "GitHub Actions" for the deploy to work —
   otherwise the workflow fails at the deploy step on merge. Also summarise the
   removed dependencies, the new one-file-per-meetup contributor flow, and the
   dropped analytics/next-event fetch.
